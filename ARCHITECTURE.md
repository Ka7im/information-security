# Архитектура системы

Учебное приложение на Node.js 24+, TypeScript, React, WebSocket и PostgreSQL 17. Инструкция запуска — в [README](README.md), полный обмен — в [AUTHENTICATION](AUTHENTICATION.md).

## Компоненты

- `apps/backend`: запуск HTTP/WebSocket, миграции, сессии, RSA, Telegram Bot API.
- `apps/server-ui`: создание пользователей с RSA и просмотр статуса Telegram, серверный журнал.
- `apps/client`: получение challenge, пароль и Telegram-код, вычисление proof через Web Crypto, профиль.
- `packages/shared`: типы операций, ответов, профиля, challenge и журнала.
- `packages/ui`: транспорт с переподключением и тайм-аутом 30 секунд, общие компоненты и журнал последних 500 событий.

Backend слушает loopback, проверяет Origin и принимает сообщения до 16 КиБ. Канал `/ws/admin` предоставляет административные операции без отдельного пароля для локальной лабораторной; `/ws/client` предоставляет вход и профиль. Сессия и черновик RSA принадлежат конкретному WebSocket. Одновременные запросы на одном соединении отклоняются как `BUSY`.

## Хранение и миграции

Миграции запускаются при старте и командой `db:migrate` в транзакции с advisory lock. Версии фиксируются в `schema_migrations`.

| Версия | Данные                                                                                                               |
| ------ | -------------------------------------------------------------------------------------------------------------------- |
| 1      | `users`: UUID, уникальный логин, password_hash, telegram_login, параметры RSA, дата создания                         |
| 2      | `auth_challenges`: user_id, t (16 байтов), created_at, expires_at                                                    |
| 3      | `users.telegram_chat_id`, `users.telegram_user_id`; `telegram_codes`: user_id, code (6 цифр), created_at, expires_at |

Telegram ID сохраняются строками. Новые поля пользователей nullable: существующие аккаунты сохраняются и ожидают `/start`. Код хранится непосредственно в БД согласно заданию. Обновление истёкших t и кода происходит при запросе, без фонового удаления. Повторные запросы и успешный вход не продлевают сроки. Внешние ключи удаляют соответствующие записи при удалении пользователя.

`auth/challenge-repository.ts` и `telegram/repository.ts` блокируют строку пользователя при получении или обновлении значений, чтобы параллельные запросы не создавали разные действующие значения. HTTP-отправка выполняется после завершения транзакции, без удержания SQL-блокировок.

## Telegram

`telegram/bot.ts` реализует подменяемый интерфейс `TelegramSender.sendCode(chatId, login, code, expiresAt)`. Реальный адаптер вызывает HTTPS Bot API через `fetch`, ограничивает отправку 10 секундами и скрывает технические ошибки и токен от клиента и журналов.

Токен читается только backend из `TELEGRAM_BOT_TOKEN`. При запуске `getMe` определяет имя бота, затем один цикл long polling вызывает `getUpdates` с timeout 25 секунд и сетевым ограничением 30 секунд. После обработки обновлений сдвигается offset. Сетевые сбои повторяются через 5 секунд; завершение приложения отменяет запросы и ожидание через AbortController, затем закрывает WebSocket и БД.

`/start` в личном чате сопоставляет username без учёта регистра и начального @. Привязка допускается при отсутствии владельца или совпадении Telegram user ID; существующий другой владелец не заменяется. Все соответствующие учебные аккаунты могут привязаться к одному Telegram. Команда повторяема. При изменении привязки сервер рассылает `users.changed`.

При отсутствии токена действует адаптер, возвращающий `TELEGRAM_UNAVAILABLE`; обхода второго фактора нет. Бот должен работать без webhook и без другого polling-процесса с тем же токеном.

## Протокол

Запрос: `{id, type, payload}`. Успех: `{id, ok: true, data}`. Ошибка: `{id, ok: false, error: {code, message}}`. Payload обязателен, в том числе `{}`. JSON и поля проверяются строгими Zod-схемами; SQL использует параметры.

| Операция         | Вход                               | Результат                                       |
| ---------------- | ---------------------------------- | ----------------------------------------------- |
| `rsa.generate`   | `{}`                               | RSA-параметры                                   |
| `users.create`   | `{login, password, telegramLogin}` | User, включая RSA и telegramLinked              |
| `users.list`     | `{}`                               | User[]                                          |
| `auth.challenge` | `{login}`                          | `{challengeHash, expiresAt, telegramExpiresAt}` |
| `auth.login`     | `{proof}`                          | Profile                                         |
| `auth.me`        | `{}`                               | Profile                                         |
| `auth.logout`    | `{}`                               | null                                            |

Profile содержит id, login, telegramLogin, createdAt. Код, его отдельный хеш, chat ID и токен не входят в публичные ответы. События: `users.changed` и `auth.log` с entry `{id, attemptId, time, side, step, message}`.

`AuthSession` связывает пользователя, SHA-256(t), сроки и время создания кода с соединением только после успешной доставки. Проверка требует действительность обоих сроков и соответствие кода БД сохранённому поколению. Успех очищает challenge, сохраняя авторизацию и код в БД. Повторный запрос challenge сбрасывает прежнюю авторизацию.

Формула: `SHA-256(password_hash + challengeHash + SHA-256(tgМетка))`. Три внутренних хеша — lowercase hex, внешний хеш считается от UTF-8 конкатенации длиной 192 символа. Код хешируется как шестизначная десятичная строка, t — как исходные байты. Сравнение использует `timingSafeEqual`.

## Интерфейс и ошибки

Клиент сначала запрашивает challenge, затем показывает пароль, поле из шести цифр и срок кода. Повторная отправка повторяет запрос challenge, очищает поля и сохраняет исходный срок действующего кода. Таймер ориентируется на ближайший из двух сроков. Отключение, истечение срока и смена логина сбрасывают форму; счётчик поколения защищает от применения запоздавших ответов к сброшенной форме.

| Код ошибки                     | Причина                                     |
| ------------------------------ | ------------------------------------------- |
| `INVALID_REQUEST`              | Некорректные JSON, payload или формат proof |
| `FORBIDDEN`, `BUSY`            | Неверный канал или уже выполняющийся запрос |
| `RSA_REQUIRED`, `LOGIN_EXISTS` | Нет черновика RSA или занят логин           |
| `INVALID_CREDENTIALS`          | Нет пользователя либо неверный пароль/код   |
| `CHALLENGE_REQUIRED`           | На соединении нет активного challenge       |
| `CHALLENGE_EXPIRED`            | Истёк t                                     |
| `TELEGRAM_CODE_EXPIRED`        | Истёк или заменён Telegram-код              |
| `TELEGRAM_NOT_LINKED`          | Пользователь ещё не выполнил /start         |
| `TELEGRAM_UNAVAILABLE`         | Бот не настроен, ошибка API или тайм-аут    |
| `UNAUTHORIZED`                 | Нет авторизованной сессии                   |
| `DATABASE_ERROR`               | Непредвиденная внутренняя ошибка            |

Клиентский журнал показывает SHA-256(t) и H; серверный дополнительно t и H′. Пароль, его отдельный хеш, Telegram-код, его отдельный хеш и токен не журналируются. Сроки ограничивают вход, но не уже установленную сессию.

## Проверки и учебные условия

`crypto.test.ts` проверяет RSA и согласованность браузерной/серверной формулы. `telegram.test.ts` проверяет отправку, обработку ошибок API, сокрытие токена, offset и остановку polling. `integration.test.ts` использует настоящие PostgreSQL и WebSocket, отдельную случайную схему и подменённый Telegram-транспорт. Часы передаются зависимостью, поэтому границы 10 минут и 24 часов проверяются без ожидания.

Пароль хранится как SHA-256 без соли по условию лабораторной. RSA-2048 имеет e=65537, параметры хранятся десятичными строками и показываются только в серверном интерфейсе; RSA не шифрует канал. Одинаковые пароль, t и код дают одинаковый proof: код повторно используется 10 минут по заданию. SHA-256 не заменяет шифрование канала.
